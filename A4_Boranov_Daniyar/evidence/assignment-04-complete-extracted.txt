Assignment #04


   New feature: room selection
    ● Extend the prototype from one room to a small fictional catalog
      of at least FOUR rooms.

    ● Each room must have an ID, name, capacity, equipment list,
      blocked status and its own bookings.

    ● Display only rooms satisfying the user’s selected requirements.

    ● The availability check must use the chosen room bookings, not
      another room’s data.
Assignment #04


   New feature: filtering rules
   F1. Capacity filter: room capacity must be greater than or equal to
   requested attendees.

   F2. Equipment filter: room must contain ALL selected required items.

   F3. A blocked room cannot be reported as available.

Assignment #04


   Task #01 - Codebase analysis
    ● Give your AI assistant a concise repository map, acceptance
      criteria and project constraints.

    ● Identify at least THREE maintainability risks, supported by
      file/function references.

    ● Propose a prioritized improvement plan before editing code.

    ● Explain one AI suggestion you rejected or modified.
Assignment #04


   Task #02 - Feature extension
    ● Add room catalog and filtering by capacity and equipment.

    ● Preserve original time and overlap validation.

    ● Use fictional data only; keep the interface responsive.

    ● Demonstrate successful and unsuccessful filtering, room
      switching, and availability checks.
Assignment #04


   Task #03 - Refactoring
    ● Separate room data, booking/availability rules, filtering logic and
      UI presentation.

    ● Reduce duplicated validation or rendering logic.

    ● Keep behavior consistent before and after refactoring.

    ● Supply a before/after module or component diagram and justify
      at least TWO design decisions.
Assignment #04


   Task #04 - Automated testing
    ● Run at least TEN executable tests.

    ● Include original AC1–AC5 regression checks and new F1–F5 tests.

    ● Cover boundaries: exactly 120 vs 121 minutes; touching vs
      overlapping intervals; exact capacity vs insufficient capacity.

    ● Add at least ONE integration or UI behavior check.

    ● Record actual commands and pass/fail results.
Assignment #04


   Task #05 - Quality evaluation
   Compare original and final versions using a short evidence table:
      ○ Automated tests passed / total
      ○ Number of duplicated logic locations removed
      ○ Code structure: modules/components and responsibilities
      ○ At least one remaining limitation

   Do not invent metrics; explain how each measure was obtained.
Assignment #04


   Task #06 - AI reflection
   Write 200–300 words addressing:

    ●   What context did you provide the AI assistant?
    ●   Which generated suggestions were useful or incorrect?
    ●   What did you personally verify?
    ●   How did tests influence your engineering decisions?
    ●   What would you improve next?
Assignment #04


   Suggested AI workflow
    1. Inspect repository and record a baseline.
    2. Provide AI with project map and explicit requirements.
    3. Ask for a small implementation plan, not a full rewrite.
    4. Implement one change at a time.
    5. Run tests and review diffs after each change.
    6. Document evidence and unresolved limitations.
