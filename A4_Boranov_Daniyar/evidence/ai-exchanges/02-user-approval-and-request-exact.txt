## 3. New functional requirements — F1–F5

Extend the application to support at least FOUR fictional university rooms.

Use the approved room catalog from Task 1:

- A-102
- B-201
- C-303
- D-404

Use the approved fictional capacities, equipment, blocked states and booking intervals described in Task1_Codebase_Analysis.md.

Each room must have:

- room ID
- room name
- capacity
- equipment list
- blocked status
- its own existing bookings

Implement:

**F1 — Capacity filtering**

A room matches only if:

room.capacity >= requestedAttendees

Test exact capacity, insufficient capacity and larger capacity.

**F2 — Equipment filtering**

A room matches only when it contains ALL selected required equipment.

Do not use ANY-equipment matching.

Selecting no equipment should not exclude a room based on equipment.

**F3 — Blocked rooms**

A blocked room must NEVER be reported as Available.

It may remain visible in the filtered catalog if it satisfies the capacity/equipment requirements, but it must show its blocked status clearly.

**F4 — Empty state**

When no rooms satisfy the selected requirements, display a clear message explaining that no matching rooms were found.

Do not show stale availability results.

**F5 — Room switching**

When the selected room changes:

- clear or correctly refresh the previous availability result;
- use the new room's blocked status;
- use the new room's existing bookings;
- never accidentally use another room's bookings.

Additional important condition:

If filtering changes and the previously selected room is no longer included in the matching results, clear that selection and the previous availability result.

Do not continue checking a room that is no longer selectable.
