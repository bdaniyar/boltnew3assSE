## 3. Initial scope and assumptions

Use the following approved requirements baseline in the report.

### Scope Statement

The goal of this project is to create a simple Smart Campus Room Availability Checker. The system allows students to check whether a selected university room is available at a specific time.

Students can choose a start time and an end time. The system checks the time limits, room status, and existing bookings. After checking, it displays either "Available" or "Unavailable" with a clear explanation.

The application will have one responsive web page and use fictional booking data. It will only check availability and will not create or confirm bookings.

### Initial Assumptions

- The system works with one selected room.
- All times are represented as integer minutes after midnight.
- The current time (`now`) is provided and is valid (0–1439).
- The room can be available or blocked.
- Existing bookings are provided as time intervals.
- Students cannot request a time that starts now or in the past.
- The maximum allowed duration is 120 minutes.
- Existing booking data must not be changed.
- No login, database, backend, external API, or payment system is required.
- The interface must work on desktop and mobile devices.

### Possible Failure Points

**Issue 1 — Overlapping time intervals**

The system might incorrectly reject a request when its start time is exactly equal to the end time of an existing booking. These intervals should not overlap.

**Issue 2 — Starting at the current time**

The system might accept a request where `start = now`. This should be rejected because the start time must be strictly after the current time.

### Function Contract

`can_book(start, end, now, blocked, existing)`

The function receives a requested start and end time, the current time, the room's blocked status, and a list of existing bookings.

It returns True only if all booking conditions are satisfied. Otherwise, it returns False.

The function must not modify the input data.

### Initial Manual Verification Plan

I will check the function using valid and invalid time intervals. I will test overlapping bookings, touching endpoints, blocked rooms, the 120-minute limit, and requests starting at the current time. I will also check that the interface displays clear results and works on narrow screens.
