Build the first working web prototype (v1) for my Software Engineering Assignment #03.

**Project name:** Smart Campus Room Availability Checker

**Main goal:**
Create a clean, responsive, single-page application where a university student can check whether one selected room is available during a requested time interval.

This is an educational prototype. It must check availability only, not make or confirm bookings.

### Technology
- React + TypeScript + Vite
- Tailwind CSS for styling
- Client-side logic only
- Simple, readable, maintainable components
- No backend, database, authentication, external APIs, payments, or unnecessary integrations

### Required functionality (AC1–AC6)

**AC1 — Time validation**
- Candidate times are integer minutes after midnight.
- Require 0 <= start < end <= 1440.
- The start must be strictly greater than the supplied current time.
- Support 1440 as a valid end-of-day boundary.
- Reject invalid or reversed intervals.

**AC2 — Duration**
- Maximum duration is 120 minutes.
- Exactly 120 minutes must be accepted.
- 121 minutes must be rejected.

**AC3 — Blocked rooms**
- If the selected room is blocked, every booking request must be rejected.

**AC4 — Overlapping bookings**
- Reject any interval that overlaps an existing booking.
- Touching endpoints are allowed.
- Example: Existing 10:00–11:00, requested 11:00–12:00 is valid.
- Existing 10:00–11:00, requested 10:30–11:30 is invalid.

**AC5 — Availability only**
- Display a clear "Available" or "Unavailable" result.
- Do not create bookings.
- Do not update or delete existing bookings.
- Do not add "Confirm Booking" or "Reserve" buttons.
- Keep all existing booking data unchanged.

**AC6 — Usability**
- Responsive desktop and mobile layout.
- Clear validation feedback explaining why a time is invalid.
- Accessible labels and readable typography.
- The interface should remain usable on narrow screens without horizontal overflow.
